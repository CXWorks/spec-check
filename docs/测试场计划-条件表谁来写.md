# 测试场计划：条件表由谁来写，最终代码才写得对？

> 背景见 [迁移失败诊断：是文档格式，还是文档内容？](迁移失败诊断-格式还是内容.md)。那份文档里的比较都在新文档上做，新文档没有标准答案，只能看「能编译、不矛盾、不是空话」。这份计划换到一个**有标准答案**的测试场，测真正的正确率。

---

## 要回答的两个问题

1. **「Claude 写条件表 → 9B 写代码」和「Claude 直接写代码」，谁写得对的多？**
   两条路线都要用 Claude。前者用 Claude 读懂文档，9B 只负责翻译成代码；后者两步都是 Claude。如果前者比不过后者，中间加 9B 就没有价值。
2. **条件表换成 9B 自己写，最终正确率会掉多少？**
   全程只用 9B、不用 Claude，整条流程就能在本地跑。条件表本身对不对不重要，只看最终代码对不对。

---

## 测试场

- **alp14 留出的 49 条**：训练时没见过，有人工写的标准答案（`dataset_bench/splits.json` 的 `command_test`）。
- **输入用「大白话版」**：第一轮诊断时，已经把这 49 条的失败 / 成功条件改写成了 PSCI 那样的自然语言，没有伪代码，也没有 helper 函数名（`results/diag_format/round12/inputs/alp14_prose/`）。读起来像一份新文档，但标准答案还在。
- **每一步都给完整的 RMM 字典**（`training-dataset/specs/alp14/preamble.rs`，1632 行，约 1.2 万 token）。标准答案用的是字典里的函数名，比如 `AddrIsGranuleAligned`；不给字典，模型只能自己起名字，最后的代码就没法和标准答案比。第一轮那组正确率是 0，主要就是这个原因。所有组拿到的字典完全一样。

---

## 跑哪几组

每组都是同样的 49 条。

| 组 | 条件表谁写 | 代码谁写 | 回答哪个问题 |
|---|---|---|---|
| **A** | 不写条件表 | Claude | 问题 1：路线 4，直接用 Claude |
| **B** | Claude | 原始 9B | 问题 1：路线 2 |
| **C** | Claude | 微调 9B | 问题 1：路线 2 |
| **D** | 原始 9B | 原始 9B | 问题 2：全本地 |
| **E** | 微调 9B | 微调 9B | 问题 2：全本地 |
| **F** | 不写条件表 | 原始 9B | 对照：条件表这一步有没有用 |
| **G** | 不写条件表 | 微调 9B | 对照：条件表这一步有没有用 |
| **参考上限** | 不写条件表（读 RMM 原文，带伪代码表） | 微调 9B | 最理想情况下能对多少 |

- **问题 1**：A 对 B、C。
- **问题 2**：D 对 B（原始 9B 写代码，只换写条件表的一方），E 对 C（微调 9B 同理）。
- **条件表有没有用**：B、D 对 F；C、E 对 G。

## 具体怎么跑

### 写条件表

- Claude 和 9B 用**同一份提示词**：
  - 一个 RMM 格式的范例；
  - 严格写法的规则（每行 `pre:/post:` 只能是一个受限的伪代码表达式，量词必须写成 Verus 的 `forall|x: T| …`，不准有英文句子、位切片、三元运算）；
  - 完整字典，并要求「字典里有合适的名字就用字典里的，没有才新起」；
  - 然后是大白话版的原文。
- **范例换成 `RMI_REALM_ACTIVATE`**：它属于训练集，不在这 49 条里。之前用的范例 `RMI_GRANULE_DELEGATE` 恰好在这 49 条里，继续用等于把一条的答案直接给了模型。
- 条件表写完做一遍格式检查，**检查结果只记录，不淘汰任何一条**。Claude 检查不过就重写一次。9B 用的是确定性解码，重写结果完全一样，所以只写一次。两边检查不过都照样往下用。

### 写代码

- 9B：和之前所有实验同一个 prompt（v3.1）、贪心解码，再加上完整字典。读条件表的组，输入是条件表；不读条件表的组，输入是大白话版原文。
- Claude（A 组）：和 9B **一字不差的 prompt 加完整字典**，只是换成 Claude 回答（`claude-opus-5-5`）。
- 生成器加一个「给完整字典」的选项（`--preamble-mode full`），默认行为不变。

### 机器

research-secure-20 和 research-secure-30，一共 16 张 H100。不需要条件表的组（F、G、参考上限）先跑；9B 写条件表和 Claude 写条件表同时进行，条件表一好就接着跑 B–E。

## 怎么算分

和之前 98 题实验同一套：

| 指标 | 意思 |
|---|---|
| **正确** | Z3 证明它和标准答案等价。标准答案本身就是空话的那几条不算 |
| **过于宽松**（weaker） | 放行了标准答案禁止的情况。**最危险，单独列出来** |
| 过于严格（stronger） | 禁止了标准答案允许的情况 |
| 互不包含（incomparable） | 两个方向都不对 |
| 编译不过 | 用 alp14 字典编译失败 |
| 空话 | 函数体只有 `true` |

另外算一遍「能编译、不矛盾、不是空话」，方便和新文档上的数字对照。

---

## 局限

- **这是微调 9B 的主场。** 内容是 RMM，正是它训练过的东西，结果会偏向它。这里只能回答「在熟悉的内容上谁更好」，不能直接推到新文档上；新文档上的正确率仍然要等人工审核 PSCI。
- **「找错率」在这里测不出来。** 之前在 alp14 上找到的文档 bug，只有 `RMI_RTT_SET_S2AP` 一个落在这 49 条里，样本太少。
- **49 条样本不大。** 差两三条不能算有区别。

---

## 成本

- Claude：写条件表约 50 次，直接写代码约 50 次。
- 9B：写条件表 2 × 49 次，写代码 7 × 49 次。每次的 prompt 有一两万 token。
- 打分：编译 + Z3 等价检查。
- **总共大约 3 小时，全自动。** 结果出来后补进这份文档。
