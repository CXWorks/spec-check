## 这张表怎么读

### ⭐ 是什么意思

| 标记 | 含义 |
|---|---|
| ⭐⭐ **第 9 行** | **最重要的一行**。权重一个字节没改，只改了考试时给它什么，rel0 上逐项追平标准答案 |
| ⭐ **「正确」这一列** | **要优先看这一列，不是「能编译」那一列**。能编译只代表语法没错，不代表写对了。两者差一倍 |
| ⭐ **「weaker」这一列** | **最危险的一类错**：规范放行了标准答案禁止的行为。极限就是写一句「永远成立」——编译 100% 通过、允许一切。**这一列越小越好，0 是唯一可接受的** |
| ⭐ 第 1 行的 10/49 | 4B 的最好正确率出现在**什么都不给**的时候，见下面「反直觉的两点」 |
| ⭐ 第 7 行 | 9B 的最好正确率和最好编译率，但代价是 weaker 从 0 变 2 |

### ⚠️ 考卷2 的两个数字，读法完全不同（最容易读错的地方）

考卷2 每个版本的题目是这样构成的：

```
eac5:  10 项 = 4 个 TP（真 bug） + 6 个 FP（假警报）
rel0:   9 项 = 3 个 TP（真 bug） + 6 个 FP（假警报）
```

表里写的 `4/4`、`3/3` 都是 **TP 那一列**，两版加起来一共 7 个真 bug。**FP 是每版各 6 个。**

| 列 | 怎么读 |
|---|---|
| **TP** | **越高越好**。上限 eac5 是 4、rel0 是 3 |
| **FP** | **不是质量信号**。「和 gold 一样」才对，gold 是 6/6 全触发 |

**为什么 FP 全触发反而是对的**：那 6 道题**是 SCOPE 出错了**——它的证明义务漏掉了规范里确实写着的一个守卫。所以**任何忠实的规范都会在这些题上「失败」，gold 也一样**。benchmark 自己的说明写着：这些项「衡量的是流水线的精度上限，不是生成器质量」。

**而且 FP 的低分往往是假的：**

```
                    TP      FP      没跑起来的
9B 什么都不给      1/4     0/6      6 项
9B 字典+改三次     3/4     5/6      1 项
gold               4/4     6/6      0 项
```

基线那个 `0/6` **不是「它很谨慎」，是「6 个证明义务根本没跑起来」**——代码编译不过，检查压根没执行。编译率上来了 FP 才开始触发。

**所以判断标准是「离 gold 的 (4/4, 6/6) 有多近」，不是「FP 越低越好」。**

**注意别和总表里的「误报」列混**：那一列是**考卷1**（纯文字检查）的误报，**那个是真的越低越好**，gold 是 0。

### 考卷2 的答案是谁定的

**题目是机器出的，判分标准是人定的：**

- 10 项里有 9 项来自 `scope --mode reason`（SCOPE 是自动工具，它生成这些证明义务）
- 1 项来自手工确认的已知 bug
- **哪些算真 bug（TP/FP 标签）是人打的**

这也解释了为什么会有 6 道错题：**出题的是工具，工具会出错，人只是在事后给每道题贴了标签。**

### 哪一个是 eval dataset

**⭐「留出集 49 条」那三列，才是真正的 eval dataset。**

- 这 49 条命令，**模型训练时一次都没见过**
- 评测统一在 `alp14` 这个版本的文档文本上做
- 「正确」= 用 Z3 定理证明器证明与标准答案**语义等价**（不是字面相同）

**「考卷1 / 考卷2」不是 eval dataset，是两个独立的 bug-finding benchmark**：

| | 是什么 | 在多少条命令上打分 |
|---|---|---|
| 考卷1 `rule_check` | 纯文字检查：有没有把「文档没定义的输出」留空 | eac5 41 条 + rel0 41 条，其中 16 项计分 |
| 考卷2 `verus_rmm` | 真编译，让证明器判定矛盾 | eac5 计 4 项，rel0 计 3 项 |

这两张考卷会考到的 **17 条命令，训练时被强制扣掉了**，否则模型见过答案，考卷测不出任何东西。

### 配置说明：「给字典」和「改几次」是什么

**「字典」= preamble。** 模型要写的式子里会用到一堆现成零件（`AddrIsGranuleAligned(地址)`、`Granule(状态,地址).state`、`RMM_GRANULE_SIZE=4096`），**不是它发明的，是项目事先定义好的**。全部定义在一个 683 行的文件里。**里面没有任何命令的逻辑，它是字典不是答案。**

三种给法：

| 配置 | 做法 | 覆盖了标准答案实际用到的符号 |
|---|---|---|
| **不给字典** | 什么都不给，靠模型训练时记住的 | — |
| **字典=尾部200行** | 给这个文件的最后 200 行（训练时就是这么给的） | eac5 79%，**alp14 只有 49%** |
| **字典=按需选取** | 按这条命令的文档段落挑相关声明 | eac5 98%，alp14 99.6% |

**「改三次」= 编译反馈修复循环。** 模型写完 → 编译 → 报错就把错误贴回去让它自己改 → 再编译，最多三轮。

**有一条硬性护栏**：修复时如果靠「少写条件」换编译通过，会被记为 `SHRANK`。**第 9 行那次 82 条命令里 SHRANK = 0**，没有一次作弊。

### 反直觉的两点（表里最该注意的）

**1. 给字典能提高编译率，但只有 9B 能把它转化成正确率。**

```
4B:  编译 18 → 21 条 (+3)     正确 10 →  9 条 (−1)   weaker 1 → 2
9B:  编译 22 → 29 条 (+7)     正确 11 → 16 条 (+5)   weaker 0 → 2
```

**4B 多出来的三条 Verus 全接受，没有一条是对的。** 这正是这个项目在训练时明令禁止的那笔交易（不许用「编译成功」当训练信号），只不过换到考试阶段出现了。

**2. 编译最好的配置，恰好是把最重要的性质丢得最彻底的。**

9B 的 weaker：不给字典 **0** → 尾部 1 → 按需选取 2。

**如果论文要写「9B 零 weaker」这个 claim，支持它的配置是「什么都不给」，不是表里成绩最好的那行。**

### 空格子为什么是空的

不是忘了跑，是这些格子**没有意义或没必要**：

- **第 2、3、6、7 行的考卷列**：这几行是为了单独测「给字典」这一个变量，跑在留出集上。考卷是另一套流程。

- **标准答案的「正确」**：跟自己比没有意义。

## 第一部分：先把基础讲清楚

### 我们要解决的问题

ARM 有一份几百页的规范文档（PDF），叫 RMM 规范。里面每条命令都有一段描述，告诉你：

- 这条命令接收什么输入
- 什么情况下会失败
- 成功了会改变什么
- 哪些状态允许被改动

**这份文档是人写的，所以它会有错**：说了有个输出却从来没说它等于什么、两处描述互相矛盾、该写的条件漏了。

**我们的目标：让 AI 自动找出这些文档漏洞。**

### 怎么找

不能直接让 AI「读一遍说哪里有问题」——那样它会瞎猜。做法是：

1. 让模型把每条命令的文字描述，翻译成一种**数学化的精确写法**（叫 Verus 代码）
2. 这种写法可以交给一个自动定理证明器（Z3）去检查
3. 如果文档本身有矛盾，翻译出来的数学式子就会矛盾，**机器能自动发现**

打个比方：文档是一篇散文，我们让模型把它翻译成方程组，然后让计算机去解方程。方程解不出来 / 解出矛盾，就说明原文有问题。

### 几个必须知道的词

| 词 | 大白话 |
|---|---|
| **Verus** | 一种给程序写「数学规格」的语言。模型要输出的就是它。 |
| **编译通过** | 模型写的东西**语法没错、名字没写错**，机器能读懂。**注意：这不代表写对了。** |
| **gold（标准答案）** | 人工写好的正确 Verus 版本，用来对照模型写得对不对。**但它也是人写的，也会错。** |
| **preamble** | 见下面单独一节。 |

### preamble 是什么（这个最重要）

**它是一本「词汇表」。**

模型要写的那段数学式子，里面会用到很多现成的函数和类型，比如：

```
AddrIsGranuleAligned(地址)    ← 判断地址是否对齐
Granule(状态, 地址).state      ← 取出某块内存的状态
RMM_GRANULE_SIZE = 4096        ← 一个常量
```

这些**不是模型自己发明的**，是这个项目事先定义好的一套「零件」。全部定义写在一个文件里，就叫 preamble。eac5 版本的 preamble 有 **683 行**，里面有 84 个函数、36 个枚举、31 个结构体、7 个常量。

**preamble 里面没有任何一条命令的逻辑。它不是答案，是字典。**

模型必须用字典里的名字，而且要拼对、参数个数对、类型对。一旦：

- 用了字典里没有的名字 → 编译报错「找不到这个符号」
- 参数个数写错 → 编译报错「这个函数要 3 个参数你给了 4 个」
- 类型对不上 → 编译报错「类型不匹配」

**这三类错误，占了全部失败的绝大多数。**

### 两张考卷

| 考卷 | 考什么 | 满分 |
|---|---|---|
| **rule_check** | 纯文字检查：模型有没有把「文档没定义的输出」留成空白。留空 = 发现了漏洞 | 16 项 |
| **verus_rmm** | 要真的编译，让证明器去判定矛盾。难得多 | eac5 4 项 / rel0 3 项 |

**verus_rmm 有个关键概念叫 `inconclusive`（无结论）**：模型写的东西编译不过，检查根本没跑起来。这**不是 0 分，是「没考」**——后面会看到这个区别害我犯过错。

## 第一点五部分：模型是怎么训练的，评测集是怎么来的

（这两块之前的版本漏掉了，补上。）

### 两个模型的训练配置

两个都是 **LoRA 微调**（不动原模型的权重，只在旁边挂一小组可训练参数），配置完全一样，**只有底座模型不同**：

| | `sft3-0` | `sft3-2` |
|---|---|---|
| 底座模型 | Qwen/Qwen3-4B | Qwen/Qwen3.5-9B |
| 精度 | bf16 | bf16 |
| 方法 | LoRA | LoRA |
| LoRA rank / alpha / dropout | 16 / 32 / 0.05 | 16 / 32 / 0.05 |
| 挂在哪些层 | q,k,v,o,gate,up,down 全挂 | 同左 |
| 轮数 | 3 | 3 |
| 学习率 | 2e-4 | 2e-4 |
| 单卡 batch / 梯度累积 | 1 / 4 | 1 / 4 |
| 最长序列 | 12288 token | 12288 token |
| 训练种子 | 42 | 42 |
| 硬件 | 单节点 8×H100 | 单节点 8×H100 |
| 训练数据 | `dataset_bench` | `dataset_bench` |

**「只有底座不同」很重要**：4B 和 9B 的差距是模型大小造成的，不是超参调出来的。

**一个刻意的设计**：训练种子只影响「参数怎么初始化、数据以什么顺序喂」，**不影响训练/测试怎么切分**（那个由另一个固定的种子决定）。所以跑三个种子副本时，三次考的是同一张卷子，差异只来自训练本身。

### 训练数据长什么样

```
dataset_bench: 训练 1266 条 / 验证 91 条 / 测试 49 条

训练的 1266 条里：
  教字典里的函数怎么用    726 条 (57%)
  教字典里的类型          291 条 (23%)
  真正的任务（文档→数学） 249 条 (20%)  ← 只涉及 72 个不同的命令
```

### 那些数字（41 / 49 / 81 / 98 / 121）分别是什么

这几个数容易混，一次讲清楚。

**同一条命令在不同版本的文档里都会出现**，规范一共有 6 个版本：

```
alp11  alp12  alp13  alp14   ← 四个较新的草案版
eac5   rel0                  ← 两个较早的版本
```

| 数字 | 是什么 |
|---|---|
| **121** | 6 个版本加起来，**去重后的命令总数**。切分就是在这 121 个名字上做的 |
| **72 / 49** | 切分结果：**72 个名字用来训练，49 个名字完全不给模型看** |
| **49** | = 随机抽的 40 个 ∪ 强制扣掉的 17 个（两者有 8 个重叠）|
| **17** | **两张考卷会考到的命令**。必须强制扣掉，否则模型训练时就见过答案了 |
| **98** | `alp14` 这一个版本里有多少条命令。**评测统一在 alp14 的文本上做** |
| **81** | 98 − 17 = 交叉验证用的池子（alp14 里不属于考卷的那些）|
| **41** | `eac5` 有 41 条命令，`rel0` 也有 41 条。**这不是评测集**，只是这两个版本各有多少条命令。两张考卷是在这 82 个文件上打分的 |

**为什么必须扣掉那 17 条**：两张考卷检查的是「模型有没有把文档没定义的输出留空」。**标准答案也是留空的——那正是要找的漏洞**。所以一个在这条命令上训练过的模型，会照抄这个留空，不管它有没有真的读懂文档。扣掉之前，这两张考卷测不出任何东西。

代价是训练数据少了 15%（293 → 249 条任务样本）。**实测这 15% 的代价是零**，两个模型分数都没掉。

## 第二部分：我做出来的最好结果

### 一个字节的权重都没改，成绩翻了三倍

模型是训练好的现成 checkpoint，我**没有重新训练**。我只改了「考试的时候给它看什么、给它几次修改机会」：

- **给它 preamble**（把字典摊开在它面前）
- **让它看编译错误后改三次**（每次编译报错，把错误贴给它，让它自己改）

```
sft3-2 (9B 模型)         verus_rmm       verus_rmm
                          eac5            rel0
什么都不给                 1/4             1/3
+ 字典 + 改三次         **3/4**         **3/3**  ← 和 gold 一模一样
gold（标准答案）            4/4             3/3
```

**rel0 上 3/3，逐项与标准答案相同。**

小模型（4B）也从 0/4、1/3 提到 2/4、2/3。

### 但「追平 gold」这四个字，我做了四个对照才敢说

因为 `3/3` 这个数字**本身什么都证明不了**——一个把所有东西都判成矛盾的垃圾答案，也会让所有检查都触发。所以我在**同一份产物**上查了四件事：

```
rel0, 41 条命令        改之前    改之后      标准答案
找到的真 bug            1/3      **3/3**      3/3
能编译                 23/41    **33/41**    41/41
Z3 证明与标准答案等价   13/41    **16/41**      —
weaker（危险错误）        0        **0**        0
每条式子的复杂度          —        11.2        10.4
修改时偷工减料的次数       —        **0**        —
```

四个对照的意思：

1. **不是退化。** 每条式子平均 11.2 个条件，标准答案是 10.4 —— 既没有空洞，也没有灌水。
2. **可证明正确的从 13 条增加到 16 条。** 这里剔掉了 6 条「标准答案自己什么都没约束」
   的命令——跟一个空的东西「等价」是白送的。算进去会虚高 6 条（19→22），我第一版
   草稿就是这么写的，发出来之前查出来的。
3. **零 weaker。** `weaker` 是最危险的一类错：**规范放行了标准答案禁止的行为**。极限就是写一句「永远成立」——编译百分百通过，允许一切。这一栏保持 0，非常重要。
4. **没有作弊。** 82 条命令里，没有任何一次「靠少写条件来换编译通过」。

**必须同时写下的限制**：真 bug 只有 3 项，分母太小；「编译过但和标准答案对不上」的从 2 条涨到 9 条；仍有 8/41 编译不过。

| 4B 什么都不给 | 11/16 | 0 | 0/4 | 1/3 |
| **4B + 字典 + 改三次** | 11/16 | 0 | **2/4** | **2/3** |
| 9B + 字典 + 改三次 | 16/16 | 1 | 3/4 | 3/3 |
| 标准答案 | 16/16 | 0 | 4/4 | 3/3 |

rule_check 拆开看：eac5 6/8，rel0 5/8。**脚手架没有改变 rule_check（还是 11/16），只改变了 verus_rmm。** 这符合预期——rule_check 是纯文字检查，不需要编译。

**49 条留出命令**

| 给字典的方式 | 能编译 | 正确 | weaker |
|---|---|---|---|
| 不给 | 18/49 (36.7%) | **10/49 (20.4%)** | 1 |
| 最后 200 行 | 21/49 (42.9%) | 9/49 (18.4%) | 2 |
| 按需选取 | 21/49 (42.9%) | 9/49 (18.4%) | 1 |

**4B 上给字典是净负的**：多了 3 条能编译，正确的少了 1 条，而且危险错误从 1 变 2。多出来的三条 Verus 全接受，**没有一条和标准答案一致**。

**三个训练种子**（同样的数据和超参，只有初始化和数据顺序不同）

```
4B:  36.7% / 34.7% / 34.7%   平均 35.4%   标准差 1.2pp
9B:  44.9% / 44.9% / 38.8%   平均 42.9%   标准差 3.5pp
```

**前两个 9B 种子分数一模一样，看起来比 4B 还稳。第三个种子把离散度翻了三倍。** 所以两个种子不够，而且噪声不能跨配置借用。

**交叉验证只在 4B 上做过**（把 81 条命令切五份，每条都被一个没训练过它的模型考一次）：

```
39/81 = 48.1% 能编译，标准误 5.6pp
```

之所以只做 4B：一次 12 分钟，先在便宜的模型上把「换一批命令结论还成不成立」摸清楚，再决定要不要在 9B 上付 5 倍的钱。**结论是：换一批命令，4B 和 9B 的差距就不显著了**，所以 9B 的五折没跑。

**和上一代对比**（`sft2-*` 是在没扣掉考卷命令的数据上训的）：

| | 共同的 40 条 |
|---|---|
| `sft2-0` 4B | 14/40 |
| `sft3-0` 4B | 16/40 |
| `sft2-2` 9B | 16/40 |
| `sft3-2` 9B | 20/40 |

**扣掉 15% 的数据之后分数反而略升**，虽然差异不显著（p = 0.625 和 0.344）。至少可以说：**这次「去污染」手术没有付出代价。**

## 第三部分：我推翻的自己的结论

**这一部分比上面的成绩更值得看。** 两天里我推翻了自己 8 个结论，其中好几个已经写进文档了。

### 1. 「9B 比 4B 强」—— 不成立

我说过两次这个差距显著（先说 7 个标准差，改口 2.8 个）。**两次都错。**

错在我拿的「标准差」是**同一个模型重训三次的分数波动**。这只能回答「模型今天状态稳不稳」，**回答不了「这张卷子有没有代表性」**。

我做了 5 折交叉验证（把 81 条命令切五份，轮流拿四份训练一份考试）才看清：真正的不确定度是 5.6pp，不是 2.6pp。7.5pp 的差距只有 **1.3 个标准差 = 不显著**。

**而最开始跑的 McNemar 检验给的就是 p = 0.454（看不出差别）。我绕了一大圈回到它。**

### 2. 「修复一轮把成绩从 0/4 提到 1/4」—— 不成立

重新打分发现：**没修复的本来就是 1/4。修复一轮什么都没变。**

记录里的 0/4 是错的。而且我是**因为一个不存在的警报**（下一条）才碰巧重跑，才发现的。没有任何一项刻意设计的检查抓到它。

### 3. 「数据被污染了」—— 根本不存在

我看到一个产物有 82 个文件，而配置写着只该有 41 个，就断定另外 41 个是脏数据，还提交了修复、写进了文档。

**实际上那个任务自己生成了全部 82 个。** 真实配置是 `GEN_VERSIONS="eac5 rel0"`，而我查它的命令**把这个值从中间的空格劈成了两半**，我把前半截当成了全部。

> **我自己查询的格式，变成了「发现」。**

### 4. 「给 preamble 能提升 22.5 个百分点，p=0.004」—— 缩水一半

那是在**去污染之前**的旧数据上测的。在干净数据上重测：4B +3 条（p=0.375），9B +5 条（p=0.227）。**都不显著。**

### 5. 「模型和标准答案在 119/136 行上不一致」—— 是我的工具坏了

我做了一个工具，把分歧定位到文档的具体某一行。它报告 136 行里 119 行不一致。

一查：**每一「行」平均匹配了 7.6 条式子**，而整条命令总共才 16 条。也就是说我在把**整个答案跟自己比了 136 遍**，根本没定位到任何地方。

修好匹配后是 74 行不一致、53 行一致。

**而且这个错误，「拿标准答案跟它自己比」的自检是永远查不出来的**——自己跟自己比，不管分得多粗都会一致。只有去看「每行匹配了几条式子」这个分布才能发现。

### 6. 「模型用错函数是因为字典被截断了」—— 例子举错了

我发现模型总是写 `RttWalk(...)`，而标准答案写 `RttWalk_(...)`（多一个参数）。我查到我们只给模型看字典的**最后 200 行**，而 `RttWalk_` 在第 75 行——在窗口外面。

结论：模型没见过那个函数。听起来完美。

**我把窗口修好后重跑，模型 273 次调用里用 `RttWalk_` 的次数仍然是 0。**

真相：**文档里从头到尾没有 `RttWalk_` 这个名字**——41 个段落一次都没出现。文档写的是 `RttWalk`。**标准答案用的 `RttWalk_` 是我们项目自己的内部约定，PDF 里根本不存在。**

所以模型不是「没看见」，**它用的是文档用的名字**。是标准答案在用一个从文档推不出来的约定。

### 7. 「文档说漏了 idr」—— 工具指对了，但机制是坏的

同一个工具，指出标准答案漏了 `RMI_VSMMU_CREATE` 的 `idr` 约束 —— **那正是我唯一手工确认过答案的案例**。我差点写下「工具独立地重新发现了已知缺陷」。

一查匹配逻辑：文档写 `vsmmu.reg_base`，Verus 写 `VsmmuAt(状态, 指针).reg_base`，共同的词只有一个，低于我设的阈值 2，所以**明明写对了的式子被判成漏了**。

> **用一个坏掉的机制命中一个已知答案，不叫验证。**

### 8. 「文档里的正确数记错了」—— 是我数错了，文档是对的

文档写 9B 正确 11 条，我数出 12 条，以为文档错了。

实际是 `PSCI_CPU_OFF` 这条命令，**标准答案自己是空的**（文档明说这条命令没有任何条件），跟一个什么都没约束的东西「等价」是白送的。文档正确地把它剔掉了。

**这次差点把对的东西改错。**

## 第四部分：一个贯穿始终的教训

八次里有六次是同一个毛病换衣服：

> **一个自动算出来的数字，没有手工读过一个具体案例，就当成结论了。**

而且它进化了三次：
- 一开始是**脚本算出来的数字**没核实
- 后来是**从工具里读出来的值**没核实（那个不存在的污染）
- 最后是**我自己造的工具**算出来的没核实（119/136）

还有一次是**用错了不确定度的来源**（种子噪声 vs 命令抽样）。

**规则最后定成这样：任何筛查结果，先手工读一个案例，再开口。** 而且「一个值」也算筛查结果 —— 从命令行读出来的东西同样要核实。

## 第五部分：三个战略问题的回答

### 问：数据是不是不够了，要不要加？

**答：证据不支持。**

我把训练集拆开数了一遍：

```
训练集 1266 条
  教字典里的函数怎么用    726 条 (57%)
  教字典里的类型          291 条 (23%)
  真正的任务（文档→数学） 249 条 (20%)  ← 只有 72 条不同的命令
```

**80% 的数据已经在教字典了。而全部失败也恰好集中在字典上**（类型不匹配 18、找不到符号 10、参数个数错 7）。**没有一个失败是「编译过了但理解错文档」。**

再加更多同类数据，大概率没用：已经有 1017 条了，模型还是不会用。而且 6 个版本已经全部用上，没有第 7 个可加。

**更关键的证据**：同一份权重，光靠考试时给它字典 + 让它改三次，成绩就从 1/4 到 3/4。**能力本来就在权重里，只是之前取不出来。**

### 问：要不要做蒸馏（让大模型教小模型）？

**答：证据不支持。**

| | rule_check（读文档） | verus_rmm（写数学式子） |
|---|---|---|
| Claude Opus 5 | 16/16 | **1/4** |
| 我们的 9B（带脚手架） | 16/16 | **3/4** |

**在我们唯一失败的那根轴上，Claude 比我们弱。老师和学生在同一个地方摔倒，蒸馏没有信息可传。**

另一种做法是「大量采样，只保留编译通过的加回训练集」。**这条路这个项目明令禁止，而且我拿到了现场证据**：

```
4B 给 preamble 之后:  编译 36.7% → 42.9%  (+3 条)
                      正确 20.4% → 18.4%  (−1 条)
                      weaker    1 → 2
```

多出来的三条编译全过，**没有一条是对的**。任何以「编译成功」为信号的训练，都在往「写一句永远成立的废话」的方向优化。

**唯一说得通的做法**：用 Z3 证明「与标准答案等价」当过滤器，而不是编译。但那需要标准答案，只在已有的 72 条命令上有 —— 只能榨现有数据的水分，引入不了新知识。

### 问：怎么保证忠于 PDF？

**答：现在根本没在测这个，这是最大的缺口。**

所有「正确率」测的都是**和标准答案一致**，不是和 PDF 一致。而标准答案是人读文档写的，**我们已经有证据它至少错一处**。

我为此建了两个新工具：

**工具一：文档溯源。** 能做的原因是——这份 PDF 不是散文，每条命令都带三张有编号的表：

```
失败条件表    gran_align → 什么情况下失败
成功条件表    gran_state → 成功后什么成立
Footprint     gran_gpt   → 允许被改动的东西
```

`gran_align` 这种编号是文档里的**稳定字符串**。所以「这条式子来自 PDF 的哪一行」是个**精确问题**，不是模糊匹配。于是三件事可查：

- 文档写了、答案没有 → **漏了**
- 答案写了、文档没有 → **编的**
- 声明了输出却从不约束 → 就是我们要找的文档漏洞

**关键是它对标准答案和对模型一视同仁**，因为锚点是文档。标准答案从此只是另一个待审对象。

现在的状态：标准答案自检覆盖率 eac5 93.8%、alp14 96.3%。

**工具二：定位到具体某一行。** 之前只能说「这条命令的答案和标准答案不一致」，说不出哪里不一致。现在可以逐行问 Z3。

用它查那 8 条不一致的命令，得到一个此前完全看不见的结果：

```
失败条件的行    一致 51 / 不一致 37  → 58% 一致
成功条件的行    一致  1 / 不一致 30  →  3% 一致
```

**模型在「什么情况下会失败」上大体是对的，在「成功后会怎样」上几乎全错。** 这是个很具体的、以前完全不知道的短板。
