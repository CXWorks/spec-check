16.1 sbi_steal_time_set_shmem command
               Sets the shared memory physical base address for steal-time accounting of the calling virtual hart. It also enables or disables steal-time information reporting by the SBI implementation.
               16.1.1 Interface
               16.1.1.1   Input values
        Name                Register     Bits        Type                                  Description
        fid                 a6           XLEN-1:0    UInt                                  FID, value 0
        shmem_phys_lo       a0           XLEN-1:0    unsigned long                         Lower XLEN bits of the shared memory physical base address. Must be 64-byte aligned. If shmem_phys_lo and shmem_phys_hi are both all-ones bitwise, steal-time reporting stops for the calling virtual hart
        shmem_phys_hi       a1           XLEN-1:0    unsigned long                         Upper XLEN bits of the shared memory physical base address
        flags               a2           XLEN-1:0    unsigned long                         Reserved for future use. Must be zero
               16.1.1.2   Output values
        Name                Register     Bits        Type                                  Description
        ret                 a0, a1       -           struct sbiret                         Command return status
               16.1.2 Failure conditions
               The section does not define any failure conditions with return codes. It requires that shmem_phys_lo is 64-byte aligned, that the shared memory is at least 64 bytes, and that flags is zero. It does not give an error code for breaking any of these requirements.
               16.1.2.1   Failure condition ordering
               The sbi_steal_time_set_shmem command does not have any failure condition orderings.
               16.1.3 Success conditions
  ID                          Condition
  shmem_addr                  pre: !IsAllOnes(shmem_phys_lo) || !IsAllOnes(shmem_phys_hi)
                              post: StealTimeShmemBase(calling_hart) == Concat(shmem_phys_hi, shmem_phys_lo)
  shmem_zero                  pre: !IsAllOnes(shmem_phys_lo) || !IsAllOnes(shmem_phys_hi)
                              post: IsZero(Mem(Concat(shmem_phys_hi, shmem_phys_lo), 64))
  report_enable               pre: !IsAllOnes(shmem_phys_lo) || !IsAllOnes(shmem_phys_hi)
                              post: StealTimeReportingEnabled(calling_hart) == TRUE
  report_disable              pre: IsAllOnes(shmem_phys_lo) && IsAllOnes(shmem_phys_hi)
                              post: StealTimeReportingEnabled(calling_hart) == FALSE
               Further behaviour:
               - Supervisor-mode software is not expected to write to the shared memory while it is used for steal-time accounting. If such a write happens, the SBI implementation must not misbehave. It may leave the shared memory filled with inconsistent data.
               - The SBI implementation must stop writing to the shared memory when the supervisor-mode software is not runnable, for example on system reset or system suspend. This avoids unnecessary work. It also allows a repeatable capture of a system image while the supervisor-mode software is suspended.
               - Table 76 (STA Shared Memory Structure) defines the shared memory layout.
               16.1.4 Footprint
    ID                        Value

    shmem_zero                Mem(Concat(shmem_phys_hi, shmem_phys_lo), 64)
