3.2.3.1 BASE_ERROR_EVENT command
               Notifies registered agents of a fatal or non-fatal platform error. The platform sends it only to agents that have registered for it, and only if it implements base error notifications. This notification is optional.
               3.2.3.1.1 Interface
               3.2.3.1.1.1   Input values
        Name                Register     Bits        Type                                  Description
        message_id          -            -           UInt32                                Message ID, value 0x0
        protocol_id         -            -           UInt32                                Protocol ID, value 0x10
               3.2.3.1.1.2   Output values
        Name                Register     Bits        Type                                  Description
        agent_id            -            31:0        UInt32                                Identifier of the agent that caused this notification
        error_status        -            31          Bool                                  Fatal. Set if the error is fatal and the platform cannot continue. Cleared if the error is non-fatal but commands have failed
                            -            30:10       -                                     Reserved, must be zero
                            -            9:0         UInt10                                Command count: number of commands in the command list. Can be zero if the error cannot be attributed
        command_list        -            -           {UInt32 message_header, UInt32 status}[N]  Commands affected by the error. Each entry is a tuple: the message header of the command, then the error status code for that command. N is the command count in error_status[9:0]
               3.2.3.1.2 Failure conditions
               The BASE_ERROR_EVENT command does not have any failure conditions.
               3.2.3.1.2.1   Failure condition ordering
               The BASE_ERROR_EVENT command does not have any failure condition orderings.
               3.2.3.1.3 Success conditions
  ID                          Condition
  notify_target               pre: IsRegisteredForBaseErrorNotification(agent) && PlatformImplementsBaseErrorNotification()
                              post: NotificationSentTo(agent)
  notify_default              pre: IsInitialBoot(agent)
                              post: !IsRegisteredForBaseErrorNotification(agent)
  fatal_set                   pre: IsFatalError()
                              post: error_status[31] == 1
  fatal_clear                 pre: !IsFatalError()
                              post: error_status[31] == 0
  status_rsvd                 post: error_status[30:10] == 0
  cmd_count                   post: error_status[9:0] == Length(command_list)
  nonfatal_list               pre: !IsFatalError()
                              post: command_list == CommandsNotProcessed()
               3.2.3.1.3.1   Usage constraints
               • Fatal error notifications are not guaranteed to be delivered. The platform must not rely on them as a way to enable recovery. A fatal error notification might include the list of messages that were being processed when the failure took place.
               • Error notifications must not be used to report that a command cannot be executed as requested because of constraints that arise in normal operation.
               3.2.3.1.4 Footprint
               The section does not identify any state that the BASE_ERROR_EVENT command modifies.
