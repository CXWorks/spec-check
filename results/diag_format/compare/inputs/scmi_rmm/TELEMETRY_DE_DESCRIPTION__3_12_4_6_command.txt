3.12.4.6 TELEMETRY_DE_DESCRIPTION command
               Supports Data Event (DE) discovery on the platform. On success, returns an array of DE descriptors. The format of each descriptor is given in DE_DESC type.
               For an example of using this kind of API, see Section 3.5.6.8.
               This command is mandatory.
               3.12.4.6.1 Interface
               3.12.4.6.1.1   Input values
        Name                Register     Bits        Type                                  Description
        message_id          Header       -           UInt                                  Message ID, value 0x4
        protocol_id         Header       -           UInt                                  Protocol ID, value 0x1B
        desc_index          Payload[0]   31:0        UInt32                                Index of the first DE descriptor to read from the DE descriptor array
               3.12.4.6.1.2   Output values
        Name                Register     Bits        Type                                  Description
        status              Payload[0]   31:0        Int32                                 Command return status. Status codes are defined in Section 3.1.4
        num_remaining       Payload[1]   31:16       UInt16                                Number of remaining DE descriptors
        num_returned        Payload[1]   15:0        UInt16                                Number of DE descriptors returned by this call
        desc[N]             Payload[2..] -           DE_DESC[N]                            Array of DE descriptors, each in DE_DESC format
               3.12.4.6.2 Failure conditions
               The section does not list any command-specific failure conditions. Status codes are defined in Section 3.1.4.
               3.12.4.6.2.1   Failure condition ordering
               The TELEMETRY_DE_DESCRIPTION command does not have any failure condition orderings.
               3.12.4.6.3 Success conditions
  ID                          Condition
  desc_count                  post: num_returned == N
  desc_first                  post: desc[0] == DeDescriptorAt(desc_index)
  desc_remaining              post: num_remaining == NumRemainingDeDescriptors(desc_index, num_returned)
  desc_format                 post: forall i < N: IsDeDescFormat(desc[i])
               3.12.4.6.4 Footprint
               The section does not say that the TELEMETRY_DE_DESCRIPTION command modifies any state.

               3.12.4.6.5 DE_DESC type
               The DE_DESC structure describes the properties of a DE, such as its unique identifier, whether it supports timestamping, and other characteristics.
        Name                         Bits        Type        Description
        de_id                        31:0        UInt32      DE identifier. Each DE has a unique 32-bit integer identifier.
        group_id                     31:0        UInt32      Event group identifier for the DE. Set to 0xFFFFFFFF if the DE does not belong to any event group.
        de_data_size                 31:0        UInt32      Actual size of the DE data in bytes. The space allocated for DE data depends on the telemetry interface: a multiple of 8 bytes for SHMTI, and a multiple of 4 bytes for FastChannels. The allocated space must hold the maximum and minimum measurable DE values, accounting for sign extension.
        de_attributes_1              31          Bool        Name specified. 1: the name field gives the DE name. 0: the name field is not present and the DE name is not specified.
                                     30          Bool        FastChannel support. 1: DE values are returned using FastChannels, and fastchannel_address_low, fastchannel_address_high and fastchannel_address_size are present. 0: no FastChannel is provisioned for this DE, and those three fields are not present.
                                     29:22       UInt8       DE type. See Table 30.
                                     21          Bool        Persistent. DE data values persist across all reboot cycles except cold reboot. The DE ID must not change across reboot cycles in which the DE data value persists.
                                     20:13       Int8        DE unit exponent. Power-of-10 multiplier, in two's complement format, applied to the unit given by the DE unit field.
                                     12:5        UInt8       DE unit. The measurement system that the DE implements. See Table 19.
                                     4:2         -           Reserved, must be zero.
                                     1:0         UInt2       Timestamp support. 0: the DE cannot provide timestamped values. 1: the DE provides timestamped values using its line timestamp. 2: the DE provides timestamped values using a block timestamp line. All other values are reserved and must not be used. Timestamps should come from a monotonic time base. Choosing the time base is outside the scope of this specification and should be agreed between the agent and the platform by other standard mechanisms.
        de_attributes_2              31:24       UInt8       DE Instance ID. Identifies DEs that measure the same DE unit (de_attributes_1[12:5]) and belong to the same Component Instance (bits[23:8]). These IDs are unsigned sequential integers starting from 0. For example, 3 DEs in the same CPU that measure temperature at different locations have DE Instance IDs 0, 1 and 2. Set to 0 if the component ID has only one instance of the DE.
                                     23:8        UInt16      Component Instance. The instance of the component that this DE belongs to. Component Instances are unsigned sequential integers starting from 0. For example, if bits[7:0] are 0x0, this field identifies the CPU instance. For CPU components, this field should follow the numeric order of the values read from the architecture-specific CPU identifier registers, for example MPIDR_EL1 in Arm A-profile CPUs. Set to 0 if the component has only one instance.
                                     7:0         UInt8       Component Type. The type of component that this DE belongs to. See Table 31.
        de_attributes_3              31:0        UInt32      Reserved, must be zero.
        line_ts_rate                 31:0        UInt32      Clock rate in kHz used to generate the line timestamp. This rate should not change. Present only if the DE uses line timestamps, as given by de_attributes_1[1:0].
        fastchannel_address_low      31:0        UInt32      Lower 32 bits of the FastChannel address. Present only if de_attributes_1[30] == 1.
        fastchannel_address_high     31:0        UInt32      Upper 32 bits of the FastChannel address. Present only if de_attributes_1[30] == 1.
        fastchannel_address_size     31:0        UInt32      Size of the FastChannel in bytes. It must hold the DE data and, if supported, the timestamps. Present only if de_attributes_1[30] == 1.
        name[16]                     -           UInt8[16]   NULL-terminated UTF-8 string of up to 16 bytes that gives the DE name. Present only if de_attributes_1[31] == 1.

  Value          Description                                     Interpretation
  0x0            Unspecified
  0x1            Accumulating - Idle/Sleep State residency       Total time spent in the idle state by the component given by Component Type and Component Instance. These values should match the idle states as presented to the agent.
  0x2            Accumulating - Idle/Sleep State count           Total count of idle state transitions by the component given by Component Type and Component Instance. These values should match the idle states as presented to the agent.
  0x3            Accumulating - others
  0x4            Instantaneous - Idle/Sleep State                Current idle state of the component given by Component Type and Component Instance. Idle states are unsigned sequential integers starting from 0. 0 is the active state, and higher values are progressively deeper power saving states.
