3.10.3.8 POWERCAP_CAP_SET command
               Sets a power cap on a power capping domain. The platform enforces the cap over the Capping Averaging Interval (CAI).
               3.10.3.8.1 Interface
               3.10.3.8.1.1   Input values
        Name                Register     Bits        Type                                  Description
        message_id          Header       -           UInt                                  Message ID, value 0x5
        protocol_id         Header       -           UInt                                  Protocol ID, value 0x18
        domain_id           Payload[0]   31:0        UInt32                                Identifier for the power capping domain
        cpli                Payload[1]   31:0        UInt32                                Concurrent power limit identifier. Must be 0 if the domain does not support CPC
        flags               Payload[2]   31:0        UInt32                                Bits[31:2]: Reserved, must be zero. Bit[1]: Async flag. Bit[0]: Ignore delayed response
        power_cap           Payload[3]   31:0        UInt32                                Power cap to set for the domain. A value of 0 disables power capping for the domain for this agent
               3.10.3.8.1.2   Output values
        Name                Register     Bits        Type                                  Description
        status              Return[0]    31:0        Int32                                 Command return status
               3.10.3.8.2 Failure conditions
  ID                          Condition
  domain_valid                pre: !IsValidPowercapDomain(domain_id)
                              post: ResultEqual(status, NOT_FOUND)
  cpli_valid                  pre: !IsValidCpli(domain_id, cpli)
                              post: ResultEqual(status, NOT_FOUND)
  req_supported               pre: !IsPowercapCapSetSupported(domain_id, cpli)
                              post: ResultEqual(status, NOT_SUPPORTED)
  cap_supported               pre: !IsSupportedPowerCap(domain_id, cpli, power_cap)
                              post: ResultEqual(status, INVALID_PARAMETERS)
  flags_reserved              pre: Bits(flags, 31, 2) != 0
                              post: ResultEqual(status, INVALID_PARAMETERS)
  flags_valid                 pre: !IsValidPowercapCapSetFlags(flags)
                              post: ResultEqual(status, INVALID_PARAMETERS)
  agent_permitted             pre: !AgentMaySetPowerCap(caller, domain_id)
                              post: ResultEqual(status, DENIED)
               3.10.3.8.2.1   Failure condition ordering
               The POWERCAP_CAP_SET command does not have any failure condition orderings.
               3.10.3.8.3 Success conditions
  ID                          Condition
  status                      post: ResultEqual(status, SUCCESS)
  agent_cap                   post: AgentRequestedPowerCap(caller, domain_id, cpli) == power_cap
  cap_disabled                post: power_cap == 0 ==> !AgentPowerCapEnabled(caller, domain_id, cpli)
  sync_done                   post: Bits(flags, 1, 1) == 0 ==> PowerCapSettingCompleted(domain_id, cpli, power_cap)
  async_queued                post: Bits(flags, 1, 1) == 1 ==> PowerCapSetRequestQueued(domain_id, cpli, power_cap)
  async_resp                  post: Bits(flags, 1, 1) == 1 && Bits(flags, 0, 0) == 0 ==> DelayedResponsePending(POWERCAP_CAP_SET_COMPLETE, domain_id)
  async_noresp                post: Bits(flags, 1, 1) == 1 && Bits(flags, 0, 0) == 1 ==> !DelayedResponsePending(POWERCAP_CAP_SET_COMPLETE, domain_id)
               3.10.3.8.4 Footprint
    ID                        Value
    agent_cap                 AgentRequestedPowerCap(caller, domain_id, cpli)
    cap_disabled              AgentPowerCapEnabled(caller, domain_id, cpli)
    enforced_cap              EnforcedPowerCap(domain_id, cpli)
    async_resp                DelayedResponsePending(POWERCAP_CAP_SET_COMPLETE, domain_id)
