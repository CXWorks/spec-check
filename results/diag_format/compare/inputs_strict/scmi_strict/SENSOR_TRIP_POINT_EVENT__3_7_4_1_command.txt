3.7.4.1 SENSOR_TRIP_POINT_EVENT command
               The platform issues this notification when a sensor crosses a trip point. The agent must have requested event notification for that trip point with the SENSOR_TRIP_POINT_CONFIG command. This notification is optional.
               3.7.4.1.1 Interface
               3.7.4.1.1.1   Input values
        Name                Register     Bits        Type                                  Description
        message_id          Header       -           UInt32                                Message identifier, value 0x0
        protocol_id         Header       -           UInt32                                Protocol identifier, value 0x15
               3.7.4.1.1.2   Output values
        Name                Register     Bits        Type                                  Description
        agent_id            Payload      31:0        UInt32                                The agent that caused this event. In the current version of the specification, this is 0: the platform generates all sensor events.
        sensor_id           Payload      31:0        UInt32                                Identifier of the sensor that has tripped
        trip_point_desc     Payload      31:17       UInt32                                Reserved
                            Payload      16          UInt32                                Direction. 1: the trip point was reached or crossed in the positive direction. 0: the trip point was reached or crossed in the negative direction.
                            Payload      15:8        UInt32                                Reserved for future use
                            Payload      7:0         UInt32                                trip_point_id: identifier of the trip point that was reached or crossed
               3.7.4.1.2 Failure conditions
               The SENSOR_TRIP_POINT_EVENT command does not have any failure conditions.
               3.7.4.1.2.1   Failure condition ordering
               The SENSOR_TRIP_POINT_EVENT command does not have any failure condition orderings.
               3.7.4.1.3 Success conditions
  ID                          Condition
  agent_id                    post: agent_id == 0
  trip_requested              post: TripPointEventRequested(sensor_id, Bits(trip_point_desc, 7, 0))
  trip_reached                post: TripPointReachedOrCrossed(sensor_id, Bits(trip_point_desc, 7, 0))
  dir_positive                post: (Bits(trip_point_desc, 16, 16) == 1) ==> TripPointCrossedInPositiveDirection(sensor_id, Bits(trip_point_desc, 7, 0))
  dir_negative                post: (Bits(trip_point_desc, 16, 16) == 0) ==> TripPointCrossedInNegativeDirection(sensor_id, Bits(trip_point_desc, 7, 0))
  multi_cross                 post: MultipleTripPointCrossingsMayBeReportedByOneNotification(sensor_id)
               3.7.4.1.4 Footprint
               The SENSOR_TRIP_POINT_EVENT command does not modify any state described in this section.
