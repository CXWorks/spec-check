3.3.2.8 POWER_STATE_NOTIFY command
               Lets the caller request POWER_STATE_CHANGED notifications from the platform when a specific power domain changes power state.
               This command is optional. Use PROTOCOL_MESSAGE_ATTRIBUTES to find out whether it is implemented.
               Notifications are disabled by default during initial boot of the platform.
               3.3.2.8.1 Interface
               3.3.2.8.1.1   Input values
        Name                Register     Bits        Type                                  Description
        message_id          Header       -           UInt32                                Message identifier, value 0x6
        protocol_id         Header       -           UInt32                                Protocol identifier, value 0x11
        domain_id           Param[0]     31:0        UInt32                                Identifier for the power domain
        notify_enable       Param[1]     31:1        UInt32                                Reserved, must be zero
                            Param[1]     0           UInt32                                Notify enable: 0 = the platform sends no POWER_STATE_CHANGED messages to the calling agent; 1 = the platform sends POWER_STATE_CHANGED messages to the calling agent when the domain changes power state
               3.3.2.8.1.2   Output values
        Name                Register     Bits        Type                                  Description
        status              Return[0]    31:0        Int32                                 Command return status
               3.3.2.8.2 Failure conditions
  ID                          Condition
  domain_valid                pre: !IsValidPowerDomain(domain_id)
                              post: ResultEqual(status, NOT_FOUND)
  notify_enable_valid         pre: !IsValidNotifyEnable(notify_enable)
                              post: ResultEqual(status, INVALID_PARAMETERS)
               3.3.2.8.2.1   Failure condition ordering
               The POWER_STATE_NOTIFY command does not have any failure condition orderings.
               3.3.2.8.3 Success conditions
  ID                          Condition
  status                      post: ResultEqual(status, SUCCESS)
  notify_on                   post: Bits(notify_enable, 0, 0) == 1 ==> PowerStateChangedNotifyEnabled(CallingAgent(), domain_id)
  notify_off                  post: Bits(notify_enable, 0, 0) == 0 ==> !PowerStateChangedNotifyEnabled(CallingAgent(), domain_id)
               3.3.2.8.4 Footprint
    ID                        Value
    notify_state              PowerStateChangedNotifyEnabled(CallingAgent(), domain_id)
