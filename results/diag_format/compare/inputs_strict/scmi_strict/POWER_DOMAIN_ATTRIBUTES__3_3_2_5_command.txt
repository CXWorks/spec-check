3.3.2.5 POWER_DOMAIN_ATTRIBUTES command
               Returns the attribute flags associated with a specific power domain.
               This command is mandatory.
               3.3.2.5.1 Interface
               3.3.2.5.1.1   Input values
        Name                Register     Bits        Type                                  Description
        protocol_id         Header       -           UInt8                                 Protocol identifier, value 0x11
        message_id          Header       -           UInt8                                 Message identifier, value 0x3
        domain_id           Parameter    31:0        UInt32                                Identifier for the domain. Domain identifiers are limited to 16 bits. The platform ignores the upper 16 bits of this field.
               3.3.2.5.1.2   Output values
        Name                Register     Bits        Type                                  Description
        status              Return       31:0        Int32                                 Command return status. See Section 3.1.4 for more status code definitions.
        attributes          Return       31:0        UInt32                                Power domain attribute flags
        name                Return       -           UInt8[16]                             Null-terminated ASCII string of up to 16 bytes that describes the power domain name
               3.3.2.5.2 Failure conditions
  ID                          Condition
  domain_exists               pre: !PowerDomainExists(Bits(domain_id, 15, 0))
                              post: ResultEqual(status, NOT_FOUND)
               3.3.2.5.2.1   Failure condition ordering
               The POWER_DOMAIN_ATTRIBUTES command does not have any failure condition orderings.
               3.3.2.5.3 Success conditions
  ID                          Condition
  status                      post: ResultEqual(status, SUCCESS)
  notify_change               post: (Bits(attributes, 31, 31) == 1) == PowerStateChangeNotifySupported(Bits(domain_id, 15, 0))
  async_support               post: (Bits(attributes, 30, 30) == 1) == PowerStateAsyncSetSupported(Bits(domain_id, 15, 0))
  sync_support                post: (Bits(attributes, 29, 29) == 1) == PowerStateSyncSetSupported(Bits(domain_id, 15, 0))
  notify_change_req           post: (Bits(attributes, 28, 28) == 1) == PowerStateChangeRequestedNotifySupported(Bits(domain_id, 15, 0))
  ext_name                    post: (Bits(attributes, 27, 27) == 1) == (PowerDomainNameLength(Bits(domain_id, 15, 0)) > 16)
  reserved                    post: Bits(attributes, 26, 0) == 0
  name_short                  post: Bits(attributes, 27, 27) == 0 ==> (IsNullTerminatedAscii(name, 16) && name == PowerDomainName(Bits(domain_id, 15, 0)))
  name_ext                    post: Bits(attributes, 27, 27) == 1 ==> name == NullTerminatedPrefix(PowerDomainName(Bits(domain_id, 15, 0)), 15)
               3.3.2.5.4 Footprint
               The POWER_DOMAIN_ATTRIBUTES command does not modify any state.

               Note: For some agents, the platform might allow only registration and receipt of notifications for power domains, and might not allow those agents to set the power states of those domains. When Bit[27] of attributes is 1, the POWER_DOMAIN_NAME_GET command (Section 3.3.2.10) returns the extended power domain name.
