B4.3.60 RMI_VDEV_START

B4.3.60.1 Intended use
RMI_VDEV_START starts a VDEV. The caller provides the physical address of the RD, which identifies a Realm, and the physical address of the VDEV, which must belong to that Realm. If the command succeeds, the operation VDEV_OP_START is recorded in the VDEV and the communication state of the VDEV becomes DEV_COMM_PENDING.

B4.3.60.2 Parameters
• fid is passed in X0 and is the function identifier. Its value is 0xC40001D3.
• rd is passed in X1 and is the physical address of the RD. The RD identifies the Realm that the command operates on.
• vdev_ptr is passed in X2 and is the physical address of the VDEV. This is the VDEV that the command operates on.

B4.3.60.3 Return values
• result is returned in X0 and gives the return status of the command.

B4.3.60.4 Caller responsibilities
RMI_VDEV_START can return the following errors:
• RMI_ERROR_NOT_SUPPORTED is returned if the implementation does not support the Device Assignment feature.
• RMI_ERROR_INPUT is returned if rd is not aligned to the size of a Granule.
• RMI_ERROR_INPUT is returned if rd is not a delegable physical address.
• RMI_ERROR_INPUT is returned if the Granule at rd is not in the RD state.
• RMI_ERROR_INPUT is returned if vdev_ptr is not aligned to the size of a Granule.
• RMI_ERROR_INPUT is returned if vdev_ptr is not a delegable physical address.
• RMI_ERROR_INPUT is returned if the Granule at vdev_ptr is not in the VDEV state.
• RMI_ERROR_INPUT is returned if the VDEV at vdev_ptr does not belong to the Realm described by rd.
• RMI_ERROR_DEVICE is returned if the state of the VDEV is not VDEV_LOCKED.
• RMI_ERROR_DEVICE is returned if the communication state of the VDEV is not DEV_COMM_IDLE.

B4.3.60.5 Implementation responsibilities: order of error checks
The implementation must make the error checks in the following order:
• The check that the VDEV belongs to the Realm described by rd is made after each of these checks: rd is a delegable physical address, the Granule at rd is in the RD state, vdev_ptr is a delegable physical address, and the Granule at vdev_ptr is in the VDEV state.
• The check that the implementation supports the Device Assignment feature is made before each of these checks: rd is a delegable physical address, the Granule at rd is in the RD state, vdev_ptr is aligned to the size of a Granule, vdev_ptr is a delegable physical address, the Granule at vdev_ptr is in the VDEV state, and the VDEV belongs to the Realm described by rd.
• The check that the Granule at vdev_ptr is in the VDEV state is made before the check that the state of the VDEV is VDEV_LOCKED. It is also made before the check that the communication state of the VDEV is DEV_COMM_IDLE.

B4.3.60.6 Implementation responsibilities: successful completion
When RMI_VDEV_START succeeds:
• The operation recorded in the VDEV is VDEV_OP_START.
• The communication state of the VDEV is DEV_COMM_PENDING.

B4.3.60.7 Implementation responsibilities: state that may be modified
RMI_VDEV_START may modify only the following state:
• The operation recorded in the VDEV.
• The communication state of the VDEV.
