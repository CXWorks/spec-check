B4.3.40 RMI_RTT_FOLD

B4.3.40.1 Intended use
RMI_RTT_FOLD destroys a homogeneous primary RTT. The Host calls RMI_RTT_FOLD and identifies the target Realm, the base of the IPA range that the RTT describes, and the RTT level. The command folds the RTT into its parent RTT entry. The parent RTT entry then holds the state, and where they apply, the output address, attributes and RIPAS that all entries of the folded RTT had before the command. The Granule that held the folded RTT is returned to the DELEGATED state.

To locate the RTT, the implementation walks the Realm's primary RTT tree to ipa, targeting the level one above level (level minus one). The parent RTT entry is the entry at ipa in the RTT that this walk reaches, at the level where the walk stops. The RTT to be folded is the RTT that this parent RTT entry points to.

B4.3.40.2 Parameters
The caller passes these input values:
• fid, in X0: the function identifier, value 0xC4000166.
• rd, in X1: the physical address of the RD for the target Realm.
• ipa, in X2: the base of the IPA range that the RTT describes.
• level, in X3: the RTT level.

B4.3.40.3 Return values
The command returns these output values:
• result, in X0: the command return status.
• rtt, in X1: the physical address of the RTT that was destroyed. rtt is valid only when result is RMI_SUCCESS.

B4.3.40.4 Caller responsibilities
Before an RMI_RTT_FOLD call, the following must be observed:
• rd must be aligned to the size of a Granule, must be a delegable physical address, and the Granule at rd must be in the RD state.
• level must be a valid RTT level for the Realm and must not be the starting level of the Realm's RTT.
• ipa must be aligned to the size of the address range that one RTT entry covers at level minus one.
• ipa must be inside the Realm's IPA space, that is, less than 2 raised to the power of the Realm's IPA width.
• The RTT walk to ipa must reach level minus one, and the RTT entry it reaches must be in the TABLE state.
• The RTT that this RTT entry points to must be homogeneous.
• ipa must not be referenced by an auxiliary RTT of the Realm.

RMI_RTT_FOLD can return the following errors:
• RMI_ERROR_INPUT is returned if rd is not aligned to the size of a Granule.
• RMI_ERROR_INPUT is returned if rd is not a delegable physical address.
• RMI_ERROR_INPUT is returned if the Granule at rd is not in the RD state.
• RMI_ERROR_INPUT is returned if level is not a valid RTT level for the Realm, or if level is the starting level of the Realm's RTT.
• RMI_ERROR_INPUT is returned if ipa is not aligned to the size of the address range that one RTT entry covers at level minus one.
• RMI_ERROR_INPUT is returned if ipa is outside the Realm's IPA space, that is, if ipa is greater than or equal to 2 raised to the power of the Realm's IPA width.
• RMI_ERROR_RTT is returned if the RTT walk to ipa stops before it reaches level minus one. The level at which the walk stopped is also returned.
• RMI_ERROR_RTT is returned if the RTT entry that the walk reaches is not in the TABLE state. The level at which the walk stopped is also returned.
• RMI_ERROR_RTT is returned if the RTT that this RTT entry points to is not homogeneous. The value of level is also returned.
• RMI_ERROR_RTT is returned if ipa is referenced by an auxiliary RTT of the Realm. The level at which the walk stopped is also returned.

The implementation checks these error conditions in the following order:
• The check that rd is a delegable physical address, and the check that the Granule at rd is in the RD state, are made before these checks: whether the RTT walk reaches level minus one, whether the RTT entry that the walk reaches is in the TABLE state, whether the RTT it points to is homogeneous, and whether ipa is referenced by an auxiliary RTT.
• The check that level is valid and is not the starting level, and the check that ipa is within the Realm's IPA space, are made before these checks: whether the RTT walk reaches level minus one, and whether the RTT entry that the walk reaches is in the TABLE state.

B4.3.40.5 Implementation responsibilities
When none of the error conditions apply, RMI_RTT_FOLD returns RMI_SUCCESS, and the following hold after the command:
• The state of the parent RTT entry for ipa is set to the state that all entries in the folded RTT had before the command.
• If the folded entries were in a state other than UNASSIGNED or UNASSIGNED_NS, the output address of the parent RTT entry is set to the output address that the folded RTT entries had before the command.
• If the folded entries were in the ASSIGNED state, the parent RTT entry gets the memory attributes that the folded entries had, interpreted as for Protected memory (RTT_PROTECTED). It also gets the stage 2 access permissions that the folded entries had, interpreted with the indirect encoding (S2AP_INDIRECT).
• If the folded entries were in the ASSIGNED_NS state, the parent RTT entry gets the memory attributes that the folded entries had, interpreted as for Unprotected memory (RTT_UNPROTECTED). It also gets the stage 2 access permissions that the folded entries had, interpreted with the Realm's stage 2 access permission encoding.
• If ipa is a Protected IPA, the RIPAS of the parent RTT entry is set to the RIPAS that the folded entries had before the command.
• The Granule that held the folded RTT is in the DELEGATED state.
• The output value rtt is the address of the folded RTT.

RMI_RTT_FOLD can modify only the following state:
• The state of the Granule that the parent RTT entry points to, that is, the Granule that holds the RTT being folded.
• The parent RTT entry, that is, the entry at ipa in the RTT that the walk reaches.
