               B4.3.52.2 Failure conditions

RMI_ERROR_NOT_SUPPORTED is returned if the implementation does not support the Device Assignment feature.

RMI_ERROR_INPUT is returned if rd is not aligned to the size of a Granule.

RMI_ERROR_INPUT is returned if rd is not a delegable physical address.

RMI_ERROR_INPUT is returned if the Granule at rd is not in the RD state.

RMI_ERROR_INPUT is returned if pdev_ptr is not aligned to the size of a Granule.

RMI_ERROR_INPUT is returned if pdev_ptr is not a delegable physical address.

RMI_ERROR_INPUT is returned if the Granule at pdev_ptr is not in the PDEV state.

RMI_ERROR_INPUT is returned if vdev_ptr is not aligned to the size of a Granule.

RMI_ERROR_INPUT is returned if vdev_ptr is not a delegable physical address.

RMI_ERROR_INPUT is returned if the Granule at vdev_ptr is not in the VDEV state.

RMI_ERROR_DEVICE is returned if the VDEV is not owned by the Realm identified by rd.

RMI_ERROR_DEVICE is returned if the VDEV is not associated with the PDEV at pdev_ptr.

RMI_ERROR_DEVICE is returned if the VDEV state is not VDEV_NEW, VDEV_UNLOCKED or VDEV_ERROR.

RMI_ERROR_DEVICE is returned if the VDEV still has one or more mappings, so its num_map field is not zero.

               B4.3.52.2.1       Failure condition ordering

The check for support of the Device Assignment feature, which can return RMI_ERROR_NOT_SUPPORTED, is made before all of the following checks: the alignment, delegability and Granule state checks on rd, pdev_ptr and vdev_ptr.

The Granule state checks on rd, pdev_ptr and vdev_ptr (that the Granules are in the RD, PDEV and VDEV states) are made before all of the following checks: that the VDEV is owned by the Realm, that the VDEV is associated with the PDEV, that the VDEV is in an allowed state, and that the VDEV has no mappings.

               B4.3.52.3 Success conditions

On success, the Granule at vdev_ptr is in the DELEGATED state.

On success, every auxiliary Granule of the VDEV is in the DELEGATED state. The number of these Granules is given by the VDEV's num_aux field.

On success, the VDEV's identifier (vdev_id) is free within the Realm, so it can be used again.

On success, the VDEV's TDI identifier (tdi_id) is free within the PCIe segment of the PDEV, so it can be used again.

On success, the Realm's count of VDEVs is one less than it was before the command.

On success, the PDEV's count of VDEVs is one less than it was before the command.

On success, if the VDEV was associated with a virtual SMMU, the VDEV's virtual stream ID (vsid) is free within that virtual SMMU, so it can be used again. The virtual SMMU is the one at the address held in the VDEV's vsmmu_addr field.
