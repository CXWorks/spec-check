B4.3.61 RMI_VDEV_UNLOCK command
               Unlock a VDEV.
               B4.3.61.1 Interface
               B4.3.61.1.1   Input values
        Name                 Register    Bits         Type                                 Description
        fid                  X0          63:0         UInt64                               FID, value 0xC400018A
        rd                   X1          63:0         Address                              PA of the RD
        vdev_ptr             X2          63:0         Address                              PA of the VDEV
               B4.3.61.1.2   Context
               The RMI_VDEV_UNLOCK command operates on the following context.
        Name                 Type                       Value                                      Before   Description
        realm                RmmRealm                   RealmAt(rd)                                false    Realm
        vdev                 RmmVdev                    VdevAt(vdev_ptr)                           false    VDEV
               B4.3.61.1.3   Output values
        Name                 Register    Bits         Type                                 Description
        result               X0          63:0         RmiCommandReturnCode                 Command return status
               B4.3.61.2 Failure conditions

RMI_ERROR_NOT_SUPPORTED is returned if the implementation does not support the Device Assignment feature.

RMI_ERROR_INPUT is returned if rd is not aligned to the size of a Granule.

RMI_ERROR_INPUT is returned if rd is not the address of a delegable Granule.

RMI_ERROR_INPUT is returned if the Granule at rd is not in the RD state.

RMI_ERROR_INPUT is returned if vdev_ptr is not aligned to the size of a Granule.

RMI_ERROR_INPUT is returned if vdev_ptr is not the address of a delegable Granule.

RMI_ERROR_INPUT is returned if the Granule at vdev_ptr is not in the VDEV state.

RMI_ERROR_INPUT is returned if the VDEV at vdev_ptr does not belong to the Realm described by rd.

RMI_ERROR_DEVICE is returned if the VDEV is not in the VDEV_LOCKED, VDEV_STARTED or VDEV_ERROR state.

RMI_ERROR_DEVICE is returned if the communication state of the VDEV is not DEV_COMM_IDLE.

RMI_ERROR_DEVICE is returned if the VDEV still has one or more mappings, that is, its mapping count is not zero.

               B4.3.61.2.1     Failure condition ordering

The check that the Granule at vdev_ptr belongs to the Realm described by rd is made only after the checks that rd is a delegable address, that the Granule at rd is in the RD state, that vdev_ptr is a delegable address, and that the Granule at vdev_ptr is in the VDEV state.

The check that the Device Assignment feature is supported is made before the checks that rd is a delegable address, that the Granule at rd is in the RD state, that vdev_ptr is aligned to the size of a Granule, that vdev_ptr is a delegable address, that the Granule at vdev_ptr is in the VDEV state, and that the VDEV belongs to the Realm described by rd.

The check that the Granule at vdev_ptr is in the VDEV state is made before the checks on the VDEV state, the communication state of the VDEV, and the VDEV mapping count.

               B4.3.61.3 Success conditions

On success, DMA for the VDEV is disabled: its DMA state is VDEV_DMA_DISABLED.

On success, the pending operation of the VDEV is VDEV_OP_UNLOCK.

On success, the communication state of the VDEV is DEV_COMM_PENDING.
