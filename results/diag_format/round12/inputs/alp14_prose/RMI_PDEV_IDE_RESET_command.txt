B4.3.16 RMI_PDEV_IDE_RESET command
               Reset non-coherent IDE connection between the Root Port and the endpoint device.
               B4.3.16.1 Interface
               B4.3.16.1.1   Input values
        Name                 Register    Bits        Type                                  Description
        fid                  X0          63:0        UInt64                                FID, value 0xC4000179
        pdev_ptr             X1          63:0        Address                               PA of the PDEV
               B4.3.16.1.2   Context
               The RMI_PDEV_IDE_RESET command operates on the following context.
        Name                 Type                       Value                                      Before   Description
        pdev                 RmmPdev                    PdevAt(pdev_ptr)
               B4.3.16.1.3   Output values
        Name                 Register    Bits        Type                                  Description
        result               X0          63:0        RmiCommandReturnCode                  Command return status
               B4.3.16.2 Failure conditions

RMI_ERROR_NOT_SUPPORTED is returned if the implementation does not support Device Assignment.

RMI_ERROR_INPUT is returned if pdev_ptr is not aligned to the size of a Granule.

RMI_ERROR_INPUT is returned if pdev_ptr is not a delegable physical address.

RMI_ERROR_INPUT is returned if the Granule at pdev_ptr is not in the PDEV state.

RMI_ERROR_DEVICE is returned if the PDEV is not connected using non-coherent IDE (its ncoh_ide attribute is not IDE_TRUE).

RMI_ERROR_DEVICE is returned if the PDEV is not in the PDEV_READY state.

               B4.3.16.2.1   Failure condition ordering

The check that Device Assignment is supported comes before the three RMI_ERROR_INPUT checks on pdev_ptr: granule alignment, delegable address, and the Granule being in the PDEV state. Those three checks have no required order among themselves.

The check that the Granule at pdev_ptr is in the PDEV state comes before both RMI_ERROR_DEVICE checks: the PDEV being connected using non-coherent IDE, and the PDEV being in the PDEV_READY state. Those two checks have no required order between them.

               B4.3.16.3 Success conditions

On success, the PDEV state is PDEV_IDE_RESETTING.

On success, the PDEV communication state is DEV_COMM_PENDING.
