B4.3.53 RMI_VDEV_GET_INTERFACE_REPORT command
               Get VDEV interface report.
               B4.3.53.1 Interface
               B4.3.53.1.1   Input values
        Name                 Register    Bits        Type                                  Description
        fid                  X0          63:0        UInt64                                FID, value 0xC40001D0
        rd                   X1          63:0        Address                               PA of the RD
        vdev_ptr             X2          63:0        Address                               PA of the VDEV
               B4.3.53.1.2   Context
               The RMI_VDEV_GET_INTERFACE_REPORT command operates on the following context.
        Name                 Type                       Value                                      Before   Description
        realm                RmmRealm                   RealmAt(rd)                                false    Realm
        vdev                 RmmVdev                    VdevAt(vdev_ptr)                           false    VDEV
               B4.3.53.1.3   Output values
        Name                 Register    Bits        Type                                  Description
        result               X0          63:0        RmiCommandReturnCode                  Command return status
               B4.3.53.2 Failure conditions

RMI_ERROR_NOT_SUPPORTED is returned if the implementation does not support the Device Assignment feature.

RMI_ERROR_INPUT is returned if rd is not aligned to the size of a Granule.

RMI_ERROR_INPUT is returned if rd is not a physical address that can be delegated.

RMI_ERROR_INPUT is returned if the Granule at rd is not in the RD state.

RMI_ERROR_INPUT is returned if vdev_ptr is not aligned to the size of a Granule.

RMI_ERROR_INPUT is returned if vdev_ptr is not a physical address that can be delegated.

RMI_ERROR_INPUT is returned if the Granule at vdev_ptr is not in the VDEV state.

RMI_ERROR_INPUT is returned if the VDEV at vdev_ptr does not belong to the Realm described by rd.

RMI_ERROR_DEVICE is returned if the VDEV is in neither the VDEV_LOCKED state nor the VDEV_STARTED state.

RMI_ERROR_DEVICE is returned if the communication state of the VDEV is not DEV_COMM_IDLE.

               B4.3.53.2.1     Failure condition ordering

Before the check that the VDEV belongs to the Realm described by rd, the command checks that rd can be delegated, that the Granule at rd is in the RD state, that vdev_ptr can be delegated, and that the Granule at vdev_ptr is in the VDEV state.

The check that the implementation supports Device Assignment comes before these checks: rd can be delegated, the Granule at rd is in the RD state, vdev_ptr is aligned to the size of a Granule, vdev_ptr can be delegated, the Granule at vdev_ptr is in the VDEV state, and the VDEV belongs to the Realm described by rd.

The check that the Granule at vdev_ptr is in the VDEV state comes before the check of the VDEV state and the check of the VDEV communication state.

               B4.3.53.3 Success conditions

The pending operation of the VDEV is VDEV_OP_GET_REPORT.

The communication state of the VDEV is DEV_COMM_PENDING.
