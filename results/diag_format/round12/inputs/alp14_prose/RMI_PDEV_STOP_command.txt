               B4.3.20.2 Failure conditions

RMI_ERROR_NOT_SUPPORTED is returned if the implementation does not support the Device Assignment feature.

RMI_ERROR_INPUT is returned if pdev_ptr is not aligned to the size of a Granule.

RMI_ERROR_INPUT is returned if pdev_ptr is not a delegable physical address.

RMI_ERROR_INPUT is returned if the Granule at pdev_ptr is not in the PDEV state.

RMI_ERROR_DEVICE is returned if the PDEV is in the PDEV_COMMUNICATING, PDEV_STOPPING or PDEV_STOPPED state.

RMI_ERROR_DEVICE is returned if the PDEV still has one or more VDEVs associated with it, meaning its num_vdevs count is not zero.

               B4.3.20.2.1   Failure condition ordering

The check that the implementation supports the Device Assignment feature comes before all three checks on pdev_ptr. Those three checks are: that pdev_ptr is aligned to the size of a Granule, that it is a delegable physical address, and that the Granule at pdev_ptr is in the PDEV state.

The check that the Granule at pdev_ptr is in the PDEV state comes before two checks on the PDEV: the check on its state and the check that no VDEVs are associated with it.

No other ordering is defined between these conditions.

               B4.3.20.3 Success conditions

The PDEV is in the PDEV_STOPPING state.

The communication state of the PDEV, given by its comm_state field, is DEV_COMM_PENDING.
