B5.3.19 VCI_VOLUME_VALIDATE_MAPPING

B5.3.19.1 Intended use
VCI_VOLUME_VALIDATE_MAPPING is intended for validating Vault device memory mappings. The Vault calls the VCI_VOLUME_VALIDATE_MAPPING function and provides:
•  a Vault device identifier
•  a target LBA region
•  the base of a target DPA region
•  flags
•  the certification nonces for the device

The command operates on the following context:
•  The current Vault.
•  The current WORKER.
•  The Vault device that volume_id identifies within the current Vault.

B5.3.19.2 Parameters
VCI_VOLUME_VALIDATE_MAPPING takes the following input values:
•  fid, passed in R0, bits [63:0]. This is the function identifier, and its value is 0xC400019F.
•  volume_id, passed in R1, bits [63:0]. This is the Vault device identifier.
•  lba_base, passed in R2, bits [63:0]. This is the base of the target LBA region.
•  lba_top, passed in R3, bits [63:0]. This is the top of the target LBA region.
•  dpa_base, passed in R4, bits [63:0]. This is the base of the target DPA region.
•  flags, passed in R5, bits [63:0]. These are the device memory flags.
•  lock_nonce, passed in R6, bits [63:0]. This is the nonce that was generated on the most recent transition to the LOCKED state.
•  meas_nonce, passed in R7, bits [63:0]. This is the sequence number of the GET_MEASUREMENT request.
•  report_nonce, passed in R8, bits [63:0]. This is the sequence number of the GET_INTERFACE_REPORT request.

B5.3.19.3 Return values
VCI_VOLUME_VALIDATE_MAPPING returns the following output values:
•  result, returned in R0, bits [63:0]. This is the command return status.
•  new_lba_base, returned in R1, bits [63:0]. This is the base of the LBA region that the command did not modify.
•  response, returned in R2, bit [0]. This shows whether the Host accepted or rejected the request.

Bits [63:1] of R2 are unused and must be zero.

VCI_VOLUME_VALIDATE_MAPPING can return the following errors:
•  VCI_ERROR_STATE is returned if the Device Assignment feature is not enabled for the Vault.
•  VCI_ERROR_INPUT is returned if volume_id does not identify a VOLUME that is in use by the Vault.
•  VCI_ERROR_INPUT is returned if the state of the VOLUME is neither VOLUME_LOCKED nor VOLUME_STARTED.
•  VCI_ERROR_INPUT is returned if lba_base is not aligned to the size of a Extent.
•  VCI_ERROR_INPUT is returned if lba_top is not aligned to the size of a Extent.
•  VCI_ERROR_INPUT is returned if dpa_base is not aligned to the size of a Extent.
•  VCI_ERROR_INPUT is returned if lba_top is less than or equal to lba_base.
•  VCI_ERROR_INPUT is returned if the LBA range from lba_base to lba_top is not entirely within the protected LBA space of the Vault.
•  VCI_ERROR_DEVICE is returned if lock_nonce, meas_nonce and report_nonce do not match the certification information that is recorded for the VOLUME.

The check that the Device Assignment feature is enabled for the Vault is made before the check that volume_id identifies a VOLUME in use by the Vault.

B5.3.19.4 Implementation responsibilities
If the command succeeds, the implementation must make sure that:
•  new_lba_base is equal to the device memory address recorded in the WORKER.
•  response is the device memory response recorded in the WORKER, converted to its VCI encoding.

VCI_VOLUME_VALIDATE_MAPPING does not modify any state.
