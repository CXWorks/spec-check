B4.3.56 HCI_VOLUME_LOCK

B4.3.56.1  Intended use
HCI_VOLUME_LOCK is intended for locking a VOLUME. The Host calls HCI_VOLUME_LOCK, providing the address of the VD of a Vault and the address of a VOLUME that belongs to that Vault. If the call succeeds, the VOLUME has a pending lock operation and is waiting for device communication to complete.

B4.3.56.2  Parameters
The caller passes the following input values:
•  fid, passed in R0, is the function identifier. Its value is 0xC40001D2.
•  vd, passed in R1, is the physical address of the VD of the Vault.
•  volume_ptr, passed in R2, is the physical address of the VOLUME.

In this command, "the Vault" means the Vault described by vd, and "the VOLUME" means the VOLUME at volume_ptr.

B4.3.56.3  Return values
HCI_VOLUME_LOCK returns the following output value:
•  result, returned in R0, is the return status of the command.

B4.3.56.4  Caller responsibilities
Before an HCI_VOLUME_LOCK call the following must be observed:
•  The implementation must support the DX feature.
•  vd must be aligned to the size of a Extent, must be a enrollable physical address, and the Extent at vd must be in the VD state.
•  volume_ptr must be aligned to the size of a Extent, must be a enrollable physical address, and the Extent at volume_ptr must be in the VOLUME state.
•  The VOLUME must belong to the Vault described by vd.
•  The VOLUME's volume_state must be VOLUME_UNLOCKED, and its comm_state must be DEV_COMM_IDLE.

HCI_VOLUME_LOCK can return the following errors:
•  HCI_ERROR_NOT_SUPPORTED is returned if the implementation does not support the DX feature.
•  HCI_ERROR_INPUT is returned if vd is not aligned to the size of a Extent.
•  HCI_ERROR_INPUT is returned if vd is not a enrollable physical address.
•  HCI_ERROR_INPUT is returned if the Extent at vd is not in the VD state.
•  HCI_ERROR_INPUT is returned if volume_ptr is not aligned to the size of a Extent.
•  HCI_ERROR_INPUT is returned if volume_ptr is not a enrollable physical address.
•  HCI_ERROR_INPUT is returned if the Extent at volume_ptr is not in the VOLUME state.
•  HCI_ERROR_INPUT is returned if the VOLUME does not belong to the Vault described by vd.
•  HCI_ERROR_DEVICE is returned if the VOLUME's volume_state is not VOLUME_UNLOCKED.
•  HCI_ERROR_DEVICE is returned if the VOLUME's comm_state is not DEV_COMM_IDLE.

B4.3.56.5  Implementation responsibilities: ordering of error checks
The implementation must observe the following ordering between error checks:
•  The check that the VOLUME belongs to the Vault described by vd is made only after these checks: vd is a enrollable physical address, the Extent at vd is in the VD state, volume_ptr is a enrollable physical address, and the Extent at volume_ptr is in the VOLUME state.
•  The check that the implementation supports the DX feature is made before these checks: vd is a enrollable physical address, the Extent at vd is in the VD state, volume_ptr is aligned to the size of a Extent, volume_ptr is a enrollable physical address, the Extent at volume_ptr is in the VOLUME state, and the VOLUME belongs to the Vault described by vd.
•  The check that the Extent at volume_ptr is in the VOLUME state is made before the checks on the VOLUME's volume_state and comm_state.

B4.3.56.6  Implementation responsibilities: state changes
On success, the implementation must:
•  Set the VOLUME's pending operation to VOLUME_OP_LOCK.
•  Set the VOLUME's comm_state to DEV_COMM_PENDING.

HCI_VOLUME_LOCK may modify only the following state:
•  The VOLUME's pending operation.
•  The VOLUME's comm_state.
